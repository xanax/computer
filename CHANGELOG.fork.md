# Fork changelog

Changes made in **this fork** (`xanax/computer`), as opposed to upstream's own [`CHANGELOG.md`](CHANGELOG.md), which is left untouched so that merging upstream stays boring and conflict-free.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions track the upstream release this fork is based on, with the fork build appended per [SemVer's fork convention](https://semver.org/#spec-item-9): upstream `0.9.21` + third fork release = `0.9.21-fork.3`.

For the *reasoning* behind each change, the per-topic documents in [`notes/`](notes/) are the real record. For bugs and whether they are upstream's, see [`BUGS.md`](BUGS.md).

## [Unreleased]

Based on upstream `f9d1d8c` (2026-08-16).

### Added

- **UI performance telemetry.** A `ui_events` table (migrations `0005`, `0006`), `POST /api/ui-events` batch ingest capped at 200 events, and `GET /api/ui-events/summary` / `/recent` / `POST /prune` / `DELETE`. Summary returns count/p50/p95/max/mean per event kind, sorted slowest p95 first. Client collector in `perf.ts`: buffers, flushes every 5 s or 40 samples, `sendBeacon` on unload, best-effort throughout, disabled via `localStorage['cptr.perf.disabled']`.
- **Instrumented paths:** tab switch → paint, mount → paint per tab type, directory list/navigate/paint/prefetch, and main-thread long tasks ≥50 ms attributed to the interaction that caused them.
- **On-device text-to-speech** (`audio.tts_provider = native`) using SAPI / macOS `say` / espeak — no API key required.
- **Directory download as zip** in the file browser.
- **Terminal font size** control.
- **Terminal shortcut bar toggle** (Settings → Appearance): hides the Tab/Esc/Ctrl row for hardware keyboards.
- **Chats close rather than being marked unread,** with an × on the chat row and a close action at the end of a conversation. Closed chats return automatically when new activity makes them unread.
- **e-ink themes `bw` and `bw-dark`:** pure ink-on-paper, no greyscales and no dithering. Mid-tones are solid inversions (ink surface with paper text) or an ink border; code and diagram surfaces stay paper.
- Workspace headings render as inverted ink plates in every theme — ink background, paper label/icons, unread as a paper chip.
- **Compaction is visible in the transcript.** A checkpoint now draws a labelled rule above the message it was stamped on ("Earlier messages summarized"), so a chat that silently lost its middle is legible. `_message_dict()` reports `summary_chars` per message (the length only — the text stays in the system prompt), and a mid-turn `chat:compacted` socket event stamps the marker without waiting for a reload. Previously compaction was invisible: the transcript just got shorter.
- **Tool servers attached per workspace.** An OpenAPI or MCP server can now be attached to a single workspace instead of every one: new servers default to workspace-only, existing global servers stay global, and the workspace editor preserves the attachment when it saves its other fields. Ids live in `workspaces.data.toolServers`; `GET /api/state/tool-servers` lists the registered servers without their secrets so the workspace editor can offer them.
- **Per-workspace time on screen.** Visible time is now measured rather than inferred from the gaps between events: a `dwell` span opens while a workspace's tab is visible and closes on workspace switch, visibility change or unload, clamped at 30 minutes so a sleeping laptop is not a session of work. `GET /api/ui-events/dwell` sums those spans and each sidebar heading shows its workspace's share of the tracked total, read once on mount and drawn as paper text on the heading's ink plate. Shares under 0.5% are dropped rather than printed as a meaningless 0%, and there is deliberately no gap-attribution fallback — the figure sits next to a workspace name, so it is measured or absent.
- **A question line in the chat header.** Under the title it carries the first line of the question whose answer is on screen, and clicking it scrolls that question to just under the header — which leaves the line naming the question before it, so repeated clicks walk back up the chat. In a short chat, or before the question's own text has scrolled away, nothing is shown.
- **Read-only `ui_metrics` tool** (Admin → Models, `telemetry` group) summarising the `ui_events` samples: measured dwell per workspace, the slowest event kinds, and an inventory of what is open.
- **A `jobs` board behind the todo list** (migrations `0009`; Phases 1-2 of [`notes/NOTES-myriad-job-queue.md`](notes/NOTES-myriad-job-queue.md)). One table holds everything the workspace intends to do — `executor` says who runs it (`human`, or a model), `trigger` says when (`manual`, or `at` for one shot at a timestamp), `payload` is the briefing. `GET/POST/PATCH/DELETE /api/jobs` plus `/{id}/defer` and `/{id}/cancel` are the whole API. The old `workspace_todos` table is still written in lockstep and still safe to read, so nothing downstream had to change on the same day.
- **A deferred todo runs itself.** `defer_workspace_todo(todo_id, at, instructions=…)` (or `POST /api/jobs/{id}/defer`) hands a todo to a model at an `at` time parsed by the timers' own grammar ("30m", "2026-09-21T03:00:00Z"). A 2-second poller moves due rows `open → queued → running` and launches each as an ordinary chat turn, so tools, approval and streaming all behave as they do in a chat the human started. `parent_chat` is null for an unattended run (a fresh chat titled after the job) and set when the deferral asked to resume in place.
- **Unattended runs land for review, never as done.** A finished run settles the job at `needs_review` with its output read back from the run's own assistant message; a run that errored, a message that vanished under it, or one that outran six hours settles `failed` with `last_error`. `done` remains a human-only transition, so an agent cannot close the todo it was handed — it proposes, and the proposal goes through `todo_requests` as usual. The agent's prompt says outright that nobody will answer a question and nobody will approve a tool call.
- **Restarting is a recovery path, not a silence.** Rows left `running` by a crash are marked `failed` ("interrupted by restart") on the next boot, and a job whose chat was mid-turn is requeued rather than failed.
- **The board is in the dashboard.** The workspace dashboard's to-do list is now the queue's own view: it merges `/api/todos` with `/api/jobs` (deduped by id), and a row carries a second line only when there is something to say — `waiting to run`, `scheduled · Sep 20, 10:11 PM · in 1 hr · deepseek-flash`, `running now`, `ready to check`, `stopped`, `attempt 2`, or the error. Per row: the check toggles it, **Run later…** opens an inline form (when + model + optional extra instructions, with **Schedule** disabled until a time is typed), a chat bubble opens the run's own chat, and the × clears a pending or finished run. `needs_review` rows get a 2 px ink bar down their leading edge — a solid rule in every palette, never a grey wash. While a run is in flight the check slot becomes a **stop** button.

- **Every task the user has is now one list, at `/scheduled`.** A plain todo, a reminder waiting for its moment, a deferral a model will run, a recurring task and the runs it has produced are all rows of the one `jobs` table, grouped by workspace: `TaskList.svelte` is the page unscoped and the dashboard's board scoped to a workspace, and `/automations` (and `/automations/<id>`) redirect into it, so no schedule is reachable from only one screen.
- **Timers are tasks now.** `timer()` writes a `trigger='at'` job instead of a dormant internal chat, and its own polling loop is gone. Timers that predate the queue are folded into it at boot — same instant, same model, same destination chat, same `cancel_on` semantics — and the child chat is marked `folded` so a second boot cannot schedule the same timer twice; one caught mid-launch by a restart is recovered, and one missing its time, chat or prompt is settled as an error rather than silently dropped.
- **One scheduler for every schedule.** `task_scheduler.py` promotes due `rrule` templates into runs and moves due `at` rows `open → queued → running`, launching each as an ordinary chat turn. The automations loop and the timer worker are retired, and the boot comment says the old loop must not run again.
- **The theme is stored in a browser cookie, so the first frame is already your palette** ([`notes/NOTES-theme-cookie.md`](notes/NOTES-theme-cookie.md)). The theme is written to `cptr_theme` (`path=/`, one year, `SameSite=Lax`) whenever it changes, and read back synchronously: an inline script in `app.html` sets the classes, background, foreground and `color-scheme` — and corrects the `theme-color` meta — before the bundle is even fetched, so a load no longer paints the default palette and then repaints. The server copy is still written and still the fallback for a browser that has never set the cookie (first run, incognito); for a browser that has one, the cookie is what decides, so one account can be `bw` on the e-ink panel and `dark` on the laptop. An unreadable value is ignored and replaced rather than trusted. The cookie is deliberately not cleared at logout: the palette belongs to the display, not to the session.

### Changed

- **Automations are job rows.** Migration `0010` moves `automations` and `automation_runs` into `jobs` (`trigger='rrule'`, `executor=model_id`, each firing a child `kind='run'` row), ids preserved so webhook URLs and bookmarked run links still resolve. A paused automation becomes a paused template — an `open` template with its `rrule` and history intact is what makes ticking off today's brief unable to destroy the schedule. The legacy tables are left populated and mirrored for one release so a rollback lands on a working table, and `automations.model` in the UI is now `tasks.model`.
- **`jobs` stamps `created_at` in milliseconds and `trigger_at` in nanoseconds.** Two units had coexisted in the tree; unifying the storage put them side by side, so `0010` converts the nanoseconds `automations` used to stamp rows with, and the Tasks view formats a run's `created_at` as milliseconds — it had been divided by a million, dating every run row January 1970. A `jobs` row mixing the units would sort decades out of place.
- **File-tree listing is bounded and stat-free.** `os.scandir` with dirent classification throughout, `_TREE_IGNORE` pruned *inside* the count walk, symlinked directories never followed, all under a shared `_ScanBudget` (~1 s plus ceilings). Unreached items are marked `?` and capped counts `+`.
- **Directory listing** uses `scandir` + `dirs_only` + a 10 s TTL cache + hover prefetch: **820 ms → 302 ms** on a cold `/mnt/c` listing.
- **Command-session polling is gated on visibility.** A chat tab polls `/api/terminal/sessions` every 5 s only while it is the active tab *and* `document.visibilityState === 'visible'`, re-arming on `visibilitychange`; previously every mounted tab polled forever, hidden or not.
- **Chat tabs no longer fetch on every mount or every click.** Hidden panels skip `loadChat`; a switch reloads only if that chat streamed, compacted, or missed a reconnect while it was hidden. Socket reconnect no longer refetches every mounted chat. Idle switches keep the copy already in memory. Hidden `.persisted-tab` wrappers also set `content-visibility: hidden` so the browser skips style/layout of the off-screen subtree.
- **Concluded chats go into deep sleep.** Closing a chat (not deleting it) drops its tab so the `ChatPanel` unmounts. The row stays out of the sidebar until new activity, and a later reopen mounts a fresh tab. Workspace/home load also prunes leftover tabs for chats that are already closed.
- **A chat load carries only what the collapsed transcript draws.** Reasoning text and tool output were 48.6 MB of the 60.8 MB of stored messages, and none of it is visible until a row is expanded — the client truncates long tool output to 10k chars even then. `GET /api/chats/{id}` now sends placeholders carrying a char count instead, flags the affected messages `output_stripped`, and the full text arrives from `GET /api/chats/{id}/messages/{message_id}/output` the first time one of that message's rows is opened: the largest chat on this box went **6.60 MB → 0.66 MB (89.9%)** per open, same messages, same ids. `ask_user` calls and their answers are never trimmed, since that row renders itself expanded; a preference that keeps rows open takes `?full=1` and one response rather than a request per message.
- **A chat load reads the message table once instead of four times.** Three bookkeeping questions asked of the same chat — the newest message id, the newest non-null `model`, and the usage-checkpoint walk — each loaded every full ORM row, including the `output` column that is ~95% of the table's bytes. New header-only queries in `cptr/models/chats.py` answer them from a few columns, and `_get_chat_context_usage` checks the provider usage report before rebuilding history: full reads per load **4 → 2** (the response body, which needs the rows anyway, and the token estimate), their query time **418 ms → 204 ms**, against 20 ms for the new queries.
- **`/api/todos` is a shim over `jobs`.** Adding, toggling, renaming or deleting a todo writes both tables and emits `jobs_changed` *and* `todos_changed`, so the built sidebar and dashboard keep working unchanged while the new board is the thing that grows. Rows the board holds that are not human todos — an agent's `needs_review` output, a deferred run in flight — stay off the todo list on purpose: they are work, not the human's checklist.
- Workspace folders start expanded by default.

### Fixed

- **One unreachable provider made *every* model unresolvable — as an HTTP 500.** Resolving a model scans the configured connections, and a connection with no stored model list asks its provider. `_fetch_provider_models` is typed `list[str] | None` and returns `None` when that call fails (non-200, timeout), but the scan iterated the result directly: `for mid in None` → `TypeError: 'NoneType' object is not iterable`. So a single dead connection produced a traceback for any model id — including one a *later* connection would have matched — where the caller should have been told `400 no connection found for model: …`. The scan now treats "no models from this connection" as an empty list. Ledger: B-014, with [`tests/test_model_resolution.py`](tests/test_model_resolution.py) (fails with `TypeError` without the change).
- **A chat's proposal outlived the todo it was about.** `todo_requests` are questions to the human ("may I close this?"), and nothing settled them when the question answered itself: deleting a todo left its pending request listing an **Approve** button for a row that no longer existed, and approving it ran a no-op update. Found in the dashboard after a deferred run proposed completing its own todo and the todo was then removed. `TodoRequest.resolve_for_todo()` now settles every pending request about a job whenever that job is deleted (`Job.delete`, which covers `/api/jobs/{id}`, `/api/todos/{id}` and an approved `remove`) or the human changes the state themselves (`/api/todos/{id}/toggle`): the request whose action is exactly what just happened is recorded `approved`, the others `rejected`, so the dashboard's review list matches the board. Ledger: B-013.
- **Commit button returned HTTP 400 whenever a staged deletion was present.** `GitBar.doCommit()` re-stages the files it is about to commit; a staged deletion matches neither worktree nor index, so one unmatchable path aborted the entire `git add` batch and `/api/git/commit` was never reached. `git.py::stage()` now keeps the single-call fast path and, only on the pathspec failure, retries per path treating "nothing to stage" as a no-op.
- **Stopping a job could be ignored 25 ms after it started.** `run_job` writes `running` before it calls `start_task`, and `/api/jobs/{id}/cancel` can only cancel tasks already registered in `chat_task._tasks` — so a cancel arriving in that gap found nothing to kill, flipped the row to `cancelled` (the board read `stopped`), and the model then ran anyway; one probe's `sleep 120` finished two minutes after the human pressed stop. `run_job` now re-reads the row as late as possible before starting the turn, and if it is no longer `running` it marks the run's assistant message `cancelled` (so the chat does not dangle as a pending turn) and starts nothing. Regression test included. Ledger: B-012. `GitBar.doCommit()` re-stages the files it is about to commit; a staged deletion matches neither worktree nor index, so one unmatchable path aborted the entire `git add` batch and `/api/git/commit` was never reached. `git.py::stage()` now keeps the single-call fast path and, only on the pathspec failure, retries per path treating "nothing to stage" as a no-op.
- **Soft keyboard covered the terminal prompt** instead of resizing it — `visualViewport` / `geometrychange` handling added.
- **Solid fills wiped in the mono themes.** An unlayered rule matched `[class*='bg-white/']` by *substring*, so any element merely mentioning an alpha utility in its class list lost its background — including an invisible "Open" button with a paper label on paper. Two blocks after the wipe re-assert the two real surfaces; a sweep of all 731 distinct class strings measured wiped surfaces at 9 ink / 33 paper → **0 / 0**, invisible-text cases 13 → 5 (bw) and 64 → 5 (bw-dark).
- **Compaction reloaded from the wrong checkpoint**, so a repeatedly compacted chat re-sent history it had already summarized. `_load_message_history` scanned root→leaf and stopped at the *first* `chat_summary`, i.e. the oldest, loosest checkpoint on the branch; summaries stack, each absorbing the previous, so the newest is the one that bounds the replay. It now keeps the most recent checkpoint on the branch (which is also the point `_summary_checkpoint_message_id` stamps, so the two agree). Measured over the 158 chats in this install's DB: messages replayed per turn **17,236 → 8,119**, all 23 affected chats smaller, none larger. Regression tests in `tests/test_context_compaction.py`.
- **Perf data quality:** `ts` was page-relative rather than epoch-ms (rows reset on reload, unordered across sessions) — now epoch-ms with `perf_ms` retaining the precise intra-page clock; ambient context (tab counts, groups, viewport, visibility) now attached to every sample at *record* time rather than flush time; long tasks attributed to the preceding interaction, sub-80 ms dropped as noise; `started_hidden` / `active` flags so rAF-throttled readings from background tabs can be discounted instead of read as slowness.

### Removed

- **Mark as unread** — closing replaces it. The unread dot still clears on read; there is no longer a way to force it back.
